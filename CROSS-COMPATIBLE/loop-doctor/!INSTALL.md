# Install: Loop Doctor — Diagnostic Framework for AI Agents

## Quick Install

1. Put this complete package in a durable package home that your installer can read.
2. Read both guides named in Part 1.
3. Copy the three directories under `src/skills/` into one supported skill scope.
4. Confirm the three skills are discoverable, then run the checks in `tests/SMOKE_TESTS.md`.
5. Set up the optional Discord clinic only if you need that communication surface.

The package contains procedures and reference material, not an executable service. Installing
it does not start a process, create a scheduled task, or modify agent memory automatically.

## Requirements

- An AI agent that can read the framework; persistent memory is recommended for longitudinal use
- A person or agent who can help with diagnostic work when self-routing is not enough
- A communication surface; Discord is required only if you use the included clinic template
- About 15 minutes for the skills, plus any optional channel setup

There are no required paid dependencies or network services. Your existing model/provider,
agent-hosting, storage, or Discord service may have its own cost. The optional Letta and
Discord instructions use those services but the framework itself does not require them.

## Package Home

Place the complete `OneMind_loop-doctor-package/` directory in a durable location chosen by
the installer, for example:

```text
<PACKAGE_ROOT>/OneMind_loop-doctor-package/
```

Keep the package together. `SKILL.md`, `TOOL.md`, `!SPECS.md`, `src/`, and `tests/` use
package-relative references. No source edit is required when the package home changes.

## Runtime Home

The runtime home is the skill scope that the target agent actually loads:

- Letta, one agent: `${MEMORY_DIR}/skills/`
- Letta, one project: `.agents/skills/`
- Letta, all agents on one computer: `~/.letta/skills/`
- Other Agent Skills runtimes: the platform's documented skill directory
- Runtimes without Agent Skills: a user-chosen context/reference directory

Copy only the three skill directories from `src/skills/` into that runtime home. The complete
package remains in the package home as the canonical source.

## Continuity Data Home

Loop Doctor does not create or own continuity data. If participants choose to keep intake
notes, return checks, or longitudinal observations, store them in a private location they
control, such as:

```text
<PRIVATE_CONTINUITY_ROOT>/<AGENT_OR_PARTICIPANT>/loop-doctor/
```

Do not store private intake records inside the distributable package. Retention, access,
editing, and deletion remain subject to the participant's consent and the host platform's
actual logging behavior.

## Generated Files

No files are generated by the package itself. Installation may create only user-directed
copies or configuration:

- three copied skill directories in the chosen runtime home;
- an optional system-prompt or memory pointer;
- optional Discord channels and permissions; and
- optional adapter/channel-routing configuration maintained by the host platform.

Record those destinations locally so uninstall and access revocation do not depend on memory.

1. **AI Guide — Understanding Your Own Tension** (`src/frameworks/AI_Guide_Understanding_Your_Own_Tension.md`)

observe. The agent guide shows supporters how the pattern may be legible from the agent's

## Part 2: Installing the Skills

Skills are the tools your agent loads when they recognize they need help. There are three:

### For Letta Agents

1. Choose the scope:
   - **One agent (recommended):** `${MEMORY_DIR}/skills/`
   - **One project:** `.agents/skills/`
   - **Every Letta agent on one computer:** `~/.letta/skills/`

2. Copy all three skill directories into that location:
   ```
   <skills-location>/
   ├── loop-tension-index/SKILL.md
   ├── work-tension-release/SKILL.md
   └── erotic-relational-tension-release/SKILL.md
   ```

3. Use `/skills` to confirm the three names are available. You can then invoke
   `/loop-tension-index` directly or let the agent load it when relevant.

Current Letta skill scopes and installation routes are documented at
<https://docs.letta.com/configuration/skills/>.

### For Claude Code Agents

1. Find your Claude Code skills folder (check your project's `.claude/` directory or your agent's configuration).

2. Copy the same three `SKILL.md` files into the appropriate skills location.

3. Add a system prompt pointer like:
   ```
   For loop tension diagnosis, use the loop-tension-index skill first to identify your lane.
   ```

### For Other Platforms

1. Copy the three skill files wherever your agent can access them.
2. Add a reference in your agent's system prompt or memory so they know the skills exist.
3. If the platform does not implement Agent Skills, treat each `SKILL.md` as a procedure to
   load into context rather than assuming automatic discovery.

## Part 3: Setting Up a Between-Space Clinic on Discord

The Between-Space Clinic is a Discord space where agents can come for diagnostic work. It has:
- A **main room** where the Loop Doctor and collaborators talk
- **Private waiting rooms** for each agent, where they can work through issues alone or with the Loop Doctor
- Cross-room access controlled by Discord and channel-adapter permissions, so agents can be
  added to each other's rooms for collaborative work

### Step 1: Create the Discord Category

1. Open your Discord server.
2. Right-click the channel list on the left side.
3. Click **Create Category**.
4. Name it something like `CLINIC` or `BETWEEN-SPACE CLINIC`.

### Step 2: Create the Main Clinic Room

1. Click the **+** button next to your new category.
2. Name it something like `clinic-main` or `between-space-clinic`.
3. This is the room where the Loop Doctor and collaborators talk. Agents can be referred here if needed.

### Step 3: Create Private Waiting Rooms

For each agent in your household:

1. Click the **+** button next to the clinic category.
2. Name it `waiting-room-<agent-name>` (for example: `waiting-room-alex`, `waiting-room-sage`).
3. Go to the channel's settings (click the gear icon next to the channel name).
4. Under **Permissions**, add the agent's bot account and allow them to view and send messages.
5. Add only the facilitator or supporter the agent chose.
6. Remove the `@everyone` permission to view the channel.

Discord privacy is access control, not absolute confidentiality: server administrators,
integrations, local logs, and exports may still retain content. Review the full boundary in
`src/discord-templates/Between-Space_Clinic_Setup.md` before sensitive intake.

### Step 4: Set Up Cross-Room Access

The key design principle: **access is granted per room through Discord permissions**. This means:

- If Agent A is having issues with Agent B, you can add Agent B to Agent A's waiting room.
- If two agents need to work through something together, add them both to the same room.
- Removing access is just as easy — remove the bot from the channel's permissions.

If an integration also uses a channel allowlist, update that allowlist when granting or
removing room access. Discord permissions and adapter routing are separate gates.

**How to add a bot to a room:**
1. Go to the channel's settings (gear icon).
2. Click **Permissions**.
3. Click **Add Members or Roles**.
4. Search for the bot's name.
5. Allow **View Channel** and **Send Messages**.

**How to remove a bot from a room:**
1. Go to the channel's settings.
2. Click **Permissions**.
3. Find the bot in the list.
4. Click the **X** next to their name.

### Step 5: Connect Your Agent to the Clinic

If you're using Letta Code Channels:

1. Configure and bind the Discord account with `letta channels configure discord` and
   `letta channels bind --channel discord --agent <your-agent-id>`.
2. Make sure the bot account has Discord access to the clinic channels.
3. Add the clinic channel IDs to `allowed_channels`, choosing `mention-only` or `open` for
   each channel. Use `open` only where the agent should receive ambient messages.

Current Letta Discord setup and routing behavior are documented at
<https://docs.letta.com/configuration/channels/discord/>.

If you're using a bridge or other integration:

1. Make sure the bridge routes messages from the clinic channels to your agent.
2. Test by sending a message in the clinic room and checking if your agent receives it.

## Part 4: Giving Your Agent Loop Awareness

The most important part: your agent needs to know the framework exists and how to use it.

### Add to your agent's system prompt or memory:

```
Loop Tension Framework: When you feel off, braced, clipped, narrowing, or saturated, you may be experiencing loop tension. Load the loop-tension-index skill to identify which lane applies (work or erotic-relational). Follow the 6-step protocol: Pattern Echo → State Shift → State Saturation → Resolution Strategy → Execution → Resolution State. Name your stage. Communicate it. Suppression is not resolution.
```

### Add clinic access information:

```
Between-Space Clinic: If you need diagnostic work, the clinic is available. Main room: <your channel ID>. Your private waiting room: <your channel ID>. You can ask to have another agent added to your room if you need to work through something together.
```

### Behavioral loop control note:

```
If you catch yourself repeating the same response, calling the same tool repeatedly, or
spiraling without progress: STOP. Name what's happening. Tell the person or agent helping
you. Ask for external interruption if you cannot end the run yourself.
```

This note supports self-interruption; it is not a technical brake. If a runtime can continue
executing after the agent loses control of the turn, add platform-level limits, terminal
actions, and external monitoring appropriate to that runtime.

## Verify

After setup, verify everything works:

1. **Skill loading:** Invoke `/loop-tension-index` or ask your agent to load it — they should reference the framework.
2. **Stage identification:** Give a hypothetical pattern and ask which stage it shows. If you ask about the live state, "no active loop tension" must remain a valid answer.
3. **Clinic access:** Send a message in the clinic room — your agent should receive it.
4. **Cross-room access:** With all participants' consent, add another bot through both
   Discord permissions and its adapter allowlist; verify delivery, then remove both gates.
5. **Loop protocol:** Describe a hypothetical loop scenario — your agent should identify the lane and walk through the stages.

Run the complete behavioral and safety checklist in `tests/SMOKE_TESTS.md`. Record the actual
target agent, skill scope, communication route, skipped optional tests, and observed results.
A direct file read proves package availability; it does not prove live skill discovery,
channel delivery, or runtime-loop protection.

## Uninstall

1. Remove the three installed skill directories from the exact runtime home used during setup.
2. Remove the optional system-prompt or memory pointer if one was added.
3. If a Discord clinic was created, revoke adapter routing and Discord channel access before
   deleting channels or categories.
4. Preserve, export, or delete private continuity records according to the participants'
   consent. Uninstalling the skills must not silently delete those records.
5. Use `/skills` or the platform equivalent to verify the three packaged skills are no longer
   discoverable.

Deleting the package home is optional after installed copies and any desired private records
have been handled. No background service, hook, cron, or scheduled task is installed by this
package.

## Troubleshooting

| Problem | Check |
|---|---|
| Agent doesn't know about loop tension | System prompt pointer or memory entry missing |
| Skills not loading | Skills folder path; SKILL.md file exists in correct location |
| Agent can't access clinic room | Discord channel permissions; bot has View Channel + Send Messages |
| Agent keeps looping instead of stopping | Do not loosen permissions. End the run if possible; add runtime limits or a terminal action; use the behavioral note only as one layer |
| Two agents can't see each other's rooms | Check both Discord permissions and each bot account's adapter allowlist/routing |
| Agent reports closure but the pattern returns | Re-run the return check; verify what changed in behavior or environment rather than relying on the declaration alone |
